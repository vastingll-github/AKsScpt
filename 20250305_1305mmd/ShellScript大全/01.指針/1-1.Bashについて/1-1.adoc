
== Bashについて

[[personal-public-article-body]]
=== Bash Script 内の変数

* Bashの変数サイズは厳密な上限は存在せず、利用可能なメモリ（RAM）に依存するようです。実質的な入力限界は8192バイト程度となるケースもあるようです。 +
* 環境変数は、1024バイト（1KB）で切り捨てられるようです。 +
* 入力バッファは、 内部定義により約8192バイト。 +
* 変数名の長さは 255バイト以下が推奨。 +
* 数値の範囲: +
　32bit: (            2,147,483,647) +
　64bit: (9,223,372,036,854,775,807) +
* コマンド引数（ARG_MAX:コマンドに渡せる引数リストの合計バイト数には上限があり）
、以下のコマンドで確認できます。 +
　Ubuntu 24.04 +
　CPU: Intel® Core™ i5-8279U +
　MEM: 16GB +
....
$ getconf ARG_MAX
2097152
....

=== Bash 特殊変数、予約変数と変数

* Bashにおける「特殊変数」と「予約変数」は、シェルに最初から組み込まれている変数です。
* 「変数に名前があるか（文字列か）」「用途がスクリプト実行時情報か、シェル自身の振る舞いか」という点で以下違いがあります。
. 特殊変数（位置パラメータ・自動変数）は、スクリプトに渡された引数や、直前のコマンドの実行結果など、実行時の状態が自動的に代入される変数。名前はアルファベットではなく、数字や記号（$?, $#など）で構成されます。「Bashが自動的に値を代入する読み取り専用の変数」です。記号（$?、$@ など）や数字で表されるのが特徴です。
. 予約変数は、Bashが特定の動作を行うために参照する変数や、シェルが常に保持している変数です。ユーザーが任意に値を上書き（または設定）してBashの動作をコントロールできる大文字の英単語名（PATH、IFS など）です。 +


==== 変数役割・説明

特殊変数：シェルが「今どうなっているか（引数や結果）」を自動的に教えてくれる読み取り専用のステータス情報。 +

[cols="1,8" width="100%",options="header"]
|====================
|特殊変数名|　　　　　　　　　　説　　　明

| $$ | 実行シェルのプロセス番号(自分のPID)を格納する変数。 
| $! | 実行シェルのプロセス番号(自分のPID)を格納する変数。
| $? | 最後に実行されたコマンドの終了ステータスを格納する変数。(コマンド成功時には 0 、失敗時には 1、コマンドやエラーの種類によってはその他の数値もあり)
| $! | 最後に呼び出されたバックグラウンドプロセスのプロセス番号を格納する変数。
| $- | シェルに与えられたフラグを格納する変数。
| $1 | シェルスクリプト実行時に指定された引数を格納する変数。
| $# | シェルスクリプト実行時に指定された引数、もしくはsetコマンド実行時に指定された全パラメータが設定される変数を格納する変数。
| $0 | シェルスクリプト自身のファイル名フルパス
| $n | シェルスクリプトに与えられた引数を格納する変数。nは1,2,3…と指定できる。
| $@ | シェルスクリプト実行時に指定された全引数が設定される変数を格納する変数。デリミタを格納する環境変数 IFS にセットされた値で区切られて表示される。
| $* | シェルスクリプト実行時に指定された全引数が設定される変数を格納する変数。出力に関してはデリミタを格納する環境変数 IFS の影響を受けない。
| ${@:X:Y} | 複数のパラメータのうち、X番目以降のY個のデータを取得するための変数を格納する変数。
| !$ | 最後に実行されたコマンドに指定していた引数を格納する変数。
| $PIPESTATUS | パイプで連結した各コマンドの終了ステータスが設定される変数。
| $LINENO | この変数を使用している行の行番号が設定される変数。
|====================

====

==== 実行シェルとサブシェルの関係

以下PROMPT_COMMANDの予約変数を現在使っているbash で有効化する手順例で
サブシェル(Sub-Shell)の説明に利用する。
bash の設定~/.bashrc を編集して、それを有効化する場合通常は以下と想定する。

====
# source ~/.bashrc
====

以下のスクリプトの実行方法により、PROMPT_COMMANDが有効となるか判断できるのであれば、サブシェルの理解はできていると想定します。

Subshellchk.bash

====
#!/usr/bin/env bash

select exeno in 'ls -l' 'unset' 'pwd' 'ls -lh'
do
  echo ${exeno}
  # スクリプトを実行した親プロセスに影響するように
  # (通常のスクリプト実行で親シェルに環境変数を設定させる手法）で、
  # スクリプトの「内部」で eval を使います。
  eval PROMPT_COMMAND='${exeno}'
  break
done 

====

実行方法パターン
PROMPT_COMMAND が有効となるのは 2. と 3. です。

====
1. 相対・絶対パス指定でスクリプトを実行 +
# ./Subshellchk.bash

2. source コマンドを利用して実行 +
# source Subshellchk.bash

3. 利用中のbashで実行 +
# . Subshellchk.bash

====
